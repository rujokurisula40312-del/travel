# Схемы данных

Все данные клиента живут в **одной** Google Sheets-таблице. Структура:

- **Служебные листы** — имя начинается с `_`. Это `_config` (настройки бота) и `_audit` (журнал событий).
- **Листы туров** — все остальные листы. Каждый тур = отдельная вкладка. В этой вкладке сверху лежат метаданные тура, ниже — таблица записавшихся туристов.

Эта одна таблица — единственное место правды для клиента (ТА). Открыл вкладку нужного тура → видишь и его параметры, и весь список лидов.

---

## Лист `_config`

Настройки клиента. Бот читает один раз при старте + раз в 10 минут (или по `/reload`).

Формат — две колонки `key` / `value` (а не строка с колонками), потому что параметров мало и так удобнее редактировать вручную:

| key | value | пояснение |
|---|---|---|
| `client_id` | `svetlana_tour` | Уникальный ID клиента (для логов) |
| `agency_name` | `Светлана Тур` | Название агентства, для промпта ИИ |
| `bot_token` | `1234:ABCD...` | Токен от `@BotFather`. **Не давать доступ к таблице посторонним!** |
| `bot_name` | `СветланаТурБот` | Отображаемое имя бота |
| `tone` | `friendly` | `friendly` / `formal` — тон ИИ |
| `manager_telegram_ids` | `123456,789012` | Telegram ID менеджеров через запятую |
| `owner_telegram_id` | `123456` | Кому шлются алёрты об ошибках бота |
| `drive_folder_id` | `1aBcDeFgHiJk` | ID Google Drive-папки с PDF |
| `notion_database_id` | `xxxxxxxx-yyyy-...` | Notion-БД со страницами стран |
| `policy_url` | `https://...` | Ссылка на политику конфиденциальности |
| `consent_text_version` | `v1` | Текущая версия текста согласия |
| `enabled` | `TRUE` | Поднимать ли бота этого клиента |

---

## Лист `_audit`

Служебный журнал по требованиям ФЗ-152 (без ПД, только факты).

| Колонка | Описание |
|---|---|
| `at` | Timestamp |
| `event` | `consent_given` / `lead_created` / `lead_deleted` / `waitlist_joined` / `error` |
| `telegram_id` | Кого касается (нужно для `/delete_me`) |
| `tour_sheet` | Имя листа тура (если применимо) |
| `details` | JSON без ПД |

## Лист тура (например, «Китай апрель 2025»)

Это самый важный лист — он содержит и параметры тура, и список туристов. Структура — фиксированная: сверху метаданные, ниже разделитель, ниже таблица лидов.

### Блок 1 — метаданные тура (строки 1–14)

Формат `key` / `value` в первых двух колонках. Бот читает по фиксированным позициям ячеек (B1, B2, ...) — поэтому строки трогать нельзя.

| Ячейка | Поле | Пример | Описание |
|---|---|---|---|
| `B1` | `tour_id` | `cn-2025-04-pekin` | Уникальный ID, не меняется (для логов и audit) |
| `B2` | `country_code` | `CN` | ISO-код страны |
| `B3` | `country_name` | `Китай` | Для матча по «хочу в Китай» |
| `B4` | `country_aliases` | `Китай,КНР,China` | Через запятую, для нечёткого матча |
| `B5` | `tour_name` | `Авторский тур по Пекину` | Заголовок для туриста |
| `B6` | `date_start` | `2025-04-15` | ISO |
| `B7` | `date_end` | `2025-04-25` | ISO |
| `B8` | `price_per_person` | `185000` |  |
| `B9` | `currency` | `RUB` |  |
| `B10` | `total_seats` | `10` | Сколько мест в туре всего |
| `B11` | `available_seats` | `7` | Справочно. Менеджер обновляет вручную после оплат. |
| `B12` | `pdf_file_id` | `1aBcDeFg...` | ID файла в Google Drive (НЕ имя файла!) |
| `B13` | `notion_page_id` | `xxxxxx-...` | Страница в Notion с описанием |
| `B14` | `is_active` | `TRUE` | Скрыть тур из списка, не удаляя лист |
| `B15` | `short_description` | `10 дней, 8 городов...` | Для списка туров в боте |

> **Почему `pdf_file_id`, а не имя файла?** Имена ненадёжны: «Сейшелы.pdf» / «Сейшельские острова.pdf». Если хранить ID в ячейке — файл можно переименовать в Drive, бот не сломается.

### Блок 2 — разделитель (строка 17)

Пустая строка + строка с заголовками таблицы лидов:

```
17: lead_id | created_at | telegram_id | username | full_name | phone | email | pax | budget | notes | consent_at | consent_v | status | is_waitlist
```

### Блок 3 — лиды (строки 18+)

Каждая строка = один турист, который прошёл сценарий записи.

| Колонка | Тип | Описание |
|---|---|---|
| `lead_id` | uuid | Внутренний ID, генерирует бот |
| `created_at` | datetime | Когда турист завершил запись |
| `telegram_id` | int | Для `/delete_me` и связи менеджера |
| `username` | string | `@ivan_petrov`, может быть пусто |
| `full_name` | string | **ПД** |
| `phone` | string | **ПД** |
| `email` | string | **ПД**, опционально |
| `pax` | int | Количество человек |
| `budget` | int | Бюджет, опционально |
| `notes` | string | Свободное поле от туриста |
| `consent_at` | datetime | Когда согласился с политикой |
| `consent_v` | string | Версия текста согласия (`v1`) |
| `status` | enum | `new` / `contacted` / `paid` / `cancelled` — менеджер обновляет вручную |
| `is_waitlist` | bool | `TRUE` если на момент записи `available_seats == 0` |

### Бот добавляет лидов через `append`

Бот не пишет в фиксированные ячейки — использует `Worksheet.append_row(...)`, который добавляет строку в конец листа. Это значит, что:
- Если менеджер вручную добавит/удалит туристов вверху — бот всё равно дописывает в конец.
- Бот не может случайно перетереть метаданные сверху.

Чтобы найти, *куда* писать — бот ищет первую пустую строку после строки 17 (заголовков).

## Шаблонная вкладка `Шаблон_тура`

В таблице клиента **всегда** есть вкладка с именем `Шаблон_тура`. Она нужна, чтобы:
- Клиенту было откуда дублировать новый тур.
- Бот игнорирует её (так же, как `_*`).

Шаблон содержит метаданные с примерами и пустую таблицу лидов с заголовками. Клиент: ПКМ на вкладке → «Дублировать» → переименовывает в название тура → правит метаданные → готово.

> Конвенция игнорирования: бот пропускает листы, имя которых начинается с `_` или содержит слово `Шаблон`.

## Мастер-таблица (твой реестр SaaS)

Отдельная Google Sheets, которая принадлежит **тебе**, не клиенту. Содержит список всех клиентов:

| Колонка | Пример |
|---|---|
| `client_id` | `svetlana_tour` |
| `agency_name` | `Светлана Тур` |
| `spreadsheet_id` | `1aBcDeFgHiJk...` (ID таблицы клиента) |
| `enabled` | `TRUE` |
| `paid_until` | `2025-09-01` |
| `notes` | `Светлана, +7..., оплата ежемесячно` |

Бот при старте читает мастер-таблицу → для каждого `enabled=TRUE` поднимает инстанс с конфигом из его `_config`.

## Структура Notion-БД

Одна Notion-БД на клиента. Каждая страница = одна страна.

### Свойства страницы

| Свойство | Тип | Описание |
|---|---|---|
| `Title` | title | Название страны |
| `country_code` | text | ISO-код, ключ для поиска |
| `aliases` | multi-select | Синонимы |
| `is_published` | checkbox | Опубликована ли |
| `tags` | multi-select | `виза`, `климат`, `еда` и т.д. |

### Содержимое страницы (markdown)

Свободный текст с разделами. Бот при ответе на вопрос подгружает **всю** страницу и кладёт в контекст Claude.

```markdown
# Китай

## Виза
Гражданам РФ для туристической поездки в континентальный Китай нужна...

## Климат
Лучшее время для поездки — апрель-май и сентябрь-октябрь...

## Что взять с собой
- Загранпаспорт (срок действия > 6 мес)
- ...

## FAQ
**Можно ли пить воду из-под крана?** — Нет.
```

> **Когда переходить на эмбеддинги.** Если страниц > 30 или одна страница > 8000 токенов — стоит делать RAG. Для нишевого ТА с 5–15 направлениями fetch навсегда хватит.

## Структура Google Drive

```
📁 Travel Bot — Светлана Тур (расшарено на сервис-аккаунт + email клиента)
   ├── 📁 tours
   │    ├── 📄 cn-2025-04-pekin.pdf
   │    ├── 📄 cn-2025-09-shanhai.pdf
   │    └── 📄 sc-2025-05-mahe.pdf
   └── 📁 archive
        └── 📄 cn-2024-10-pekin.pdf  (старое, не используется)
```

> Имена файлов = `tour_id`.pdf — для удобства людей. Бот всё равно ходит по `pdf_file_id` из ячейки `B12` листа тура.

## Конфиг приложения (env vars)

Это **не** настройки клиента, а глобальные переменные процесса бота:

| Переменная | Пример |
|---|---|
| `MASTER_CONFIG_SHEET_ID` | ID мастер-таблицы со всеми клиентами |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | JSON сервис-аккаунта (base64) |
| `ANTHROPIC_API_KEY` | Claude API key |
| `NOTION_TOKEN` | Notion integration token |
| `LOG_LEVEL` | `INFO` / `DEBUG` |
| `ENV` | `dev` / `prod` |
| `SENTRY_DSN` | (опционально) |

## Доменные модели Python (наброски)

```python
@dataclass(frozen=True)
class Tour:
    """Метаданные тура, прочитанные из верхней части листа."""
    sheet_name: str           # имя вкладки в Sheets, оно же название тура для UI
    tour_id: str
    country_code: str
    country_name: str
    aliases: list[str]
    name: str
    date_start: date
    date_end: date
    price: int
    currency: str
    total_seats: int
    available_seats: int
    pdf_file_id: str
    notion_page_id: str
    short_description: str
    is_active: bool

@dataclass
class LeadDraft:
    """Заполняется во время FSM, попадает в Sheets только после consent + всех полей."""
    telegram_id: int
    username: str | None
    tour_sheet: str           # в какой лист писать
    full_name: str | None = None
    phone: str | None = None
    email: str | None = None
    pax: int | None = None
    budget: int | None = None
    notes: str | None = None
    consent_at: datetime | None = None

@dataclass(frozen=True)
class Lead:
    """Заполненный лид, готовый к записи в лист тура."""
    lead_id: str
    created_at: datetime
    tour_sheet: str
    telegram_id: int
    username: str | None
    full_name: str
    phone: str
    email: str | None
    pax: int
    budget: int | None
    notes: str | None
    consent_at: datetime
    consent_v: str
    status: Literal["new", "contacted", "paid", "cancelled"]
    is_waitlist: bool

@dataclass(frozen=True)
class AnonymousContext:
    """Что МОЖНО отправить в Claude. ПД сюда не попадают by design."""
    country_kb_markdown: str
    tour_summary: str | None
    chat_history: list[str]   # последние реплики, без идентификаторов
    user_question: str
```
