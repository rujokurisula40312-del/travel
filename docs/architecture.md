### Важно: PII-граница

ПД туристов **никогда** не уходят в Claude и Notion. Всё, что отправляется в Claude — обезличенный контекст:

> Турист интересуется Сейшелами на двоих в апреле, бюджет ~200к, спрашивает про визу.

Имя, телефон, email — только в Google Sheets, который шарится с почтой ТА в России.

## 2. Структура проекта (Python-модули)

│   ├── booking.py             # сценарий записи (FSM)
│   ├── handover.py            # перевод на менеджера
│   └── consent.py             # согласие ФЗ-152, /delete_me

├── services/

│   ├── drive.py               # выдача PDF по country_id
│   ├── notion.py              # загрузка контента страны

│   └── notifier.py            # отправка уведомлений менеджерам

│   ├── book_seat.py           # запись + декремент мест
│   ├── join_waitlist.py       # запись в лист ожидания
│   └── delete_me.py           # удаление ПД по запросу
│
├── domain/
│   ├── models.py              # dataclass: Tour, Lead, Country, ConsentRecord
│   ├── states.py              # FSM-состояния (см. conversation-flow.md)
│   └── errors.py              # доменные ошибки (CountryNotFound, NoSeats, ...)
│

│   ├── google_auth.py         # service account

│   └── logging.py

> **Принцип:** routers — тонкие, бизнес-логика — в `usecases`, внешние API — в `services`, доменные модели — в `domain`. Так проще писать тесты и переиспользовать use-case в разных хендлерах.

## 3. Ключевые потоки данных

### 3.1 Запрос «дай программу по Китаю»

```
User                Router          Usecase            Sheets           Drive
 │     /menu →       │                │                  │                │
 │ "программа Китай" │                │                  │                │
 │ ──────────────────▶                │                  │                │
 │                   │ send_program(  │                  │                │
 │                   │   country=CN)──▶                  │                │
 │                   │                │ get_country(CN)──▶                │
 │                   │                │  ◀── pdf_file_id │                │
 │                   │                │ get_pdf(file_id) ────────────────▶│
 │                   │                │  ◀────────────────── PDF bytes    │
 │                   │  ◀── PDF       │                  │                │
 │  ◀── document     │                │                  │                │
```

**Гарантия:** имя файла **не** используется как ключ. В Sheets есть колонка `pdf_file_id` (Google Drive ID). Это убирает проблему транслитерации, нескольких файлов на страну, опечаток.

### 3.2 ИИ-вопрос «нужна ли виза в Сейшелы»

```
User              ai_chat router      ai_consult uc       Notion        Claude
 │ "виза в Сейшелы?" ──▶              │                    │              │
 │                   │  ai_consult(   │                    │              │
 │                   │  text, ctx) ───▶                    │              │
 │                   │                │ get_country_kb(SC)─▶              │
 │                   │                │  ◀── markdown      │              │
 │                   │                │ build_prompt(...)  │              │
 │                   │                │ messages.create() ─────────────────▶
 │                   │                │  ◀───────────────── reply         │
 │                   │  ◀── reply     │                    │              │
 │  ◀── ответ        │                │                    │              │
```

**Что уходит в Claude:**
- системный промпт (роль, тон, ограничения, имя ТА)
- контекст страны из Notion (markdown)
- последние N реплик диалога **без** ФИО/телефона/email
- свежий вопрос пользователя

**Что НЕ уходит:**
- никакие данные из листа «Туристы»
- никаких telegram_id, имён, контактов

### 3.3 Сценарий записи на тур

См. [`conversation-flow.md`](conversation-flow.md) — подробный FSM. Здесь — ключевая часть с бронированием места:

```
                      ┌────────────────────────────────┐
                      │  Пользователь подтвердил тур   │
                      └─────────────┬──────────────────┘
                                    ▼
                      ┌────────────────────────────────┐
                      │  Запрос согласия (ФЗ-152)      │
                      │  Inline-кнопка "Согласен"      │
                      └─────────────┬──────────────────┘
                                    ▼
                      ┌────────────────────────────────┐
                      │  Сбор: ФИО → телефон → email   │
                      └─────────────┬──────────────────┘
                                    ▼
                      ┌────────────────────────────────┐
                      │  Атомарная попытка записи:     │
                      │   1. lock(tour_id)             │
                      │   2. read seats                │
                      │   3. if seats > 0:             │
                      │        write lead              │
                      │        seats -= 1              │
                      │        commit                  │
                      │      else:                     │
                      │        rollback → waitlist     │
                      │   4. unlock                    │
                      └─────────────┬──────────────────┘
                                    ▼
                      ┌────────────────────────────────┐
                      │  Уведомить менеджера(ов)       │
                      │  Подтвердить туристу           │
                      └────────────────────────────────┘
```

**Важно про гонку мест.** gspread не даёт настоящих транзакций. Варианты:

| Подход | Плюс | Минус |
|---|---|---|
| **In-process asyncio.Lock на tour_id** | Простой, работает в одном инстансе | Не работает при горизонтальном масштабировании |
| **Lock-ячейка в Sheets** (записываем `LOCKED_BY=...` и timeout) | Работает между инстансами | Медленно, гонки на самом локе |
| **Sqlite-журнал лидов** + Sheets как зеркало | Надёжно, быстро | +1 хранилище, сложнее онбординг |
| **Принять риск овербукинга** (1 место в день — допустимо) | Минимум кода | Овербукинг возможен |

> Решение нужно зафиксировать в [`open-questions.md`](open-questions.md). Для одного инстанса MVP я предлагаю **asyncio.Lock + проверка перед коммитом**, для прода — **sqlite-журнал**.

## 4. Управление состоянием диалога (FSM)

aiogram 3.x даёт `StatesGroup`. Используем `MemoryStorage` для MVP, `RedisStorage` для прода (чтобы переживать рестарт).

Ключевые группы состояний (детали в [`conversation-flow.md`](conversation-flow.md)):

```python
class Booking(StatesGroup):
    waiting_country = State()
    waiting_dates = State()
    waiting_pax = State()
    waiting_budget = State()
    waiting_consent = State()
    waiting_name = State()
    waiting_phone = State()
    waiting_email = State()
    confirming = State()

class Waitlist(StatesGroup):
    waiting_consent = State()
    waiting_contacts = State()

class Handover(StatesGroup):
    in_chat_with_manager = State()  # бот молчит, форвардит сообщения
```

Контекст диалога (`state.set_data`) хранит:
- `lead_draft` — заполняемые поля лида
- `chat_history` — последние 6 реплик для подачи в Claude (без ПД)
- `current_tour_id` — на какой тур идёт запись
- `consent_at` — timestamp согласия

## 5. Мультиклиентность (SaaS-режим)

### 5.1 Один процесс vs процесс-на-клиента

| Подход | Когда |
|---|---|
| **Процесс-на-клиента** (отдельный systemd-сервис на каждого ТА) | До 5–10 клиентов. Простая изоляция, легко обновлять одного. |
| **Один процесс, N токенов** (`Bot` инстансы в `Dispatcher`) | От 10 клиентов. Экономит память и деплой. |

> **Рекомендация для старта:** процесс-на-клиента на Railway/Selectel, через `docker-compose` с шаблоном сервиса. Когда клиентов станет 10+ — переход на multi-bot dispatcher.

### 5.2 Конфиг клиента

Один Google Sheets-документ с **несколькими листами**:

```
[Клиент: Светлана Тур]
├── config       # 1 строка: токен, ID Drive-папки, ID Notion-БД, telegram_id менеджеров, тон
├── tours        # активные туры (см. data-schemas.md)
├── leads        # записавшиеся туристы (ПД)
└── waitlist     # лист ожидания
```

Бот при старте читает `config`-лист один раз → грузит остальные ленивo с TTL-кешем.

См. полные схемы в [`data-schemas.md`](data-schemas.md).

### 5.3 Параметризация промпта

Системный промпт — Jinja2-шаблон. Подставляются: имя агентства, имя бота, тон («дружеский/официальный»), список активных направлений, контакт менеджера.

```jinja
Ты — ИИ-консультант турагентства "{{ agency_name }}".
Тон общения: {{ tone }}.
Ты можешь отвечать на вопросы о следующих направлениях: {{ countries|join(', ') }}.
...
```

## 6. Кеширование и синхронизация данных

| Данные | Где живут | Кеш | TTL |
|---|---|---|---|
| Список туров | Google Sheets | in-memory | 5 минут |
| Контент страны | Notion | in-memory | 15 минут |
| PDF | Google Drive | in-memory (bytes) | 1 час |
| Конфиг клиента | Google Sheets | in-memory | 10 минут |
| Чёрный список вопросов | Sheets | in-memory | 5 минут |

> Для MVP — простой `dict + asyncio.Event` с TTL. Для прода — `aiocache` или Redis.

**Инвалидация:** команда `/reload` для админа (telegram_id из конфига) сбрасывает все кеши вручную. Этого хватает для ТА, который обновляет туры раз в день.

## 8. Перевод на менеджера

Два варианта реализации:

| Вариант | Как работает | Плюс | Минус |
|---|---|---|---|
| **«Эстафета»** | Бот пишет менеджеру «турист X хочет связаться, telegram_id = ...», менеджер сам открывает чат с туристом. | Просто, не нужен прокси-чат. | Турист должен ещё раз начать переписку. |
| **«Прокси»** | Бот переходит в `Handover.in_chat_with_manager`, форвардит сообщения туриста менеджеру и обратно. | Бесшовно для туриста. | Сложнее, нужно следить за состоянием, риск утечки. |

> Для MVP — **«эстафета»**. Прокси — в бэклог.

## 9. Хостинг и деплой

### MVP (фазы 1–3)

- Railway, Docker, polling.
- Секреты — Railway env vars.
- Логи — stdout → Railway dashboard.
- БД пока нет (только Sheets + in-memory).

### Прод (фаза 5)

- Selectel или Yandex Cloud (по ФЗ-152).
- Один Docker-контейнер на клиента под `systemd` или `docker-compose`.
- Sentry (сервер в РФ) для ошибок.
- Telegram-алерты в личку владельца при критических ошибках (`notifier.notify_owner`).
- Бэкап `leads` и `waitlist` раз в день — в отдельный Sheets-документ.

## 10. Безопасность и ФЗ-152 (технические аспекты)

| Требование | Реализация |
|---|---|
| Согласие до сбора | FSM не пускает в `waiting_name` без `state.consent_at` |
| Локализация | Sheets шарится только на email в РФ; хостинг РФ; сервис-аккаунт Google — отдельный для прода |
| Минимизация ПД | Только ФИО, телефон, email. Паспорт **не** собираем (передаём менеджеру вживую). |
| Удаление | `/delete_me` → находит лид по `telegram_id` → удаляет строку → пишет факт удаления в `audit` лист |
| Изоляция от Claude | `claude.py` принимает только `AnonymousContext` (dataclass без ПД). Тип-чек на этапе компиляции. |
| Логи без ПД | Логгер маскирует `phone`, `email`, `full_name` через `logging.Filter` |

```python
@dataclass(frozen=True)
class AnonymousContext:
    """Всё, что МОЖНО отправить в Claude. ПД сюда не кладутся by design."""
    country_kb: str
    chat_history: list[ChatTurn]   # text only, no user identifiers
    tour_summary: str | None
    user_question: str
```
